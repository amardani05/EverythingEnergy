# Everything Energy - UI Architecture

## Design direction

**Aesthetic:** Dark editorial / terminal-grade. Think Bloomberg Terminal meets a research note from a top-tier sell-side desk. Dense without being cluttered. Restrained color palette with sharp accents reserved for signals (red = stretched, green = normal, amber = watch). Monospace numerics. Light type for body, weight reserved for hierarchy.

**Anti-goals:** No playful gradients, no pastel cards, no rounded "modern SaaS" look. This is not a consumer app - it's an analyst workstation.

**Why dark:** Energy data is read for hours at a time. Dark palette reduces fatigue. Charts and heatmaps render with more visual weight against a dark background.

## Three views

### 1. Map view (default landing)

Vertical map matching the geographic metaphor:

```
                    OCEAN
    [offshore drillers]  [OFS offshore]  [tankers]
                       |
    ===================|====================  (coastline)
                       v
                      PORT
       [LNG terminals] [refiners] [pipelines]
       [G&P midstream] [petrochem] [IOCs]
                       |
                       v
                ONSHORE SUBSURFACE
    [oil E&P] [gas E&P] [minerals/royalty]
                       |
                       v
                ONSHORE SURFACE
       [OFS onshore] [OFS equipment]
       [biofuels] [coal]
                       |
                       v
                    END USER
       [IPPs] [regulated gas] [LDCs]
       [renewables] [uranium] [SMR] [retail]
```

Each node is rendered as a card showing:
- Display name
- Representative ticker (large, bold)
- 60d residual color stripe (signal strength of best opportunity in node)
- N constituents

Edges drawn as subtle SVG arrows representing commodity flow.

Hover behavior:
- Node card lifts slightly
- Tooltip shows: representative ticker's 60d return, basket dominant driver, R²
- Edges from this node highlight (orange), others fade

Click behavior: opens **Node Detail** view (right-side drawer or full-page route).

### 2. Node Detail view

Six panels, two-column layout:

| **Left column** | **Right column** |
|---|---|
| Composition (constituent table) | Driver loadings (heatmap row) |
| Recent residual screen (top 5 over/under) | Cumulative basket return chart |
| Pairs this node participates in | Regime alerts touching this node |

**Composition** is the most important panel. Sortable table:
- Ticker | Name | MC bucket | Index | Sub-tag | Residual z (color-coded) | 60d return | YTD return | R² to basket | Dominant driver

Row click reveals expandable detail with the per-name driver loadings (CL, NG, CRACK, SPX, TNX, URA, BDRY) with t-stats.

### 3. Screener view

Cross-cutting tables for idea generation:
- All names with |z_resid_60d| > 1.5, sortable by node, residual, return
- All pairs flagged at |z| > 1.5 with thesis
- All regime alerts
- Optional: all names where `dominant != home_basket_dominant` (suggests classification mismatch worth investigating)

## Data contract

UI reads `dashboard_data.json` at page load. Single fetch, cached in localStorage.

Top-level shape:
```
{
  meta: {generated_at, taxonomy_version, n_nodes, n_constituents, lookback_years},
  drivers: ["CL", "NG", "CRACK_321", "WTI_BRENT", "SPX", "TNX", "URA", "BDRY"],
  nodes: [<NodeObj>],
  pairs: [<PairObj>],
  regime_alerts: [<RegimeObj>]
}
```

Each NodeObj has:
- `id`, `display_name`, `description`, `layer`, `representative_ticker`, `gics`
- `feeds_into[]`, `served_by_revenue_from[]` - for graph edges
- `constituents[]` - each with ticker, name, mc_bucket, index, residuals, name loadings
- `intra_corr` - basket cohesion stats
- `basket_loadings` - driver betas + t-stats at basket level
- `var_shares` - share of basket variance per driver (sums to ~R²)
- `r2`, `dominant_driver` - basket-level summary
- `cumulative_returns[]` - sampled time series for chart

## Tech stack

- **Single-file HTML** with React via CDN (no build step)
- **D3** for the map graph and time series charts (CDN)
- **Tailwind via CDN** for utility classes (PostCSS would be better for prod; for now CDN is fine)
- **EB Garamond** display font + **JetBrains Mono** for numerics + **Inter** body - three-font system, all from Google Fonts

Single file philosophy: drop `dashboard.html` and `dashboard_data.json` in any folder, open in browser. No backend. No build. The data is generated by the Python pipeline; the HTML is static.

When the analysis is updated, run `consolidate_data.py` again. Page reloads pick up the new JSON automatically.

## What's NOT in the MVP (deferred)

- Live market data (last_price is from cache, not realtime)
- News overlay on regime changes
- Backtest tooling for pair trades
- Custom basket builder
- Comparison view (basket vs basket side-by-side time series)
- Export to PowerPoint (later, via the existing pptx skill)

These are all reachable extensions once the navigation works.
